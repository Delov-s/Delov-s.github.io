记一次脱壳实战

2026-09-27 19:00:00   2026-09-27 19:00:00
分类 安卓逆向实战
标签 脱壳 Frida Android

前言:最近开始尝试一些实战了，想多总结一下app逆向的思路,毕竟其他的一些分析可以依靠ai来完成，这也是我第一次脱企业壳，app的版本也比较老

一.环境准备

软件：某江文学城

包名：com.jjwxc.reader，使用 360 加固。

使用工具：Frida 16.7.19，小米 6（ARM 真机，Android 9），frida-dexdump，deepseek网页版，dsh+v4flash，backsmali

二.脱壳工作

先尝试能不能用工具直接脱壳

把软件安装到x86模拟器，然后启动frida，但是发现frida会闪退，原因是 libjiagu.so 只有 ARM 版本，需要 libhoudini.so 翻译，加固壳在翻译层中触发自毁。于是切换到真机，spawn模式注入仍会因反调试崩溃。

调整策略使用attach模式，等app稳定之后再附加frida

查 PID 并附加：

adb shell pidof com.jjwxc.reader
frida-dexdump -U -p <PID> -d --sleep 10

成功dump出14个DEX文件

用jadx-gui打开最大的 classes07.dex，产生报错Bad dex file checksum，说明dex文件头部有损坏，使用 010 Editor 的DexFixer.1sc脚本一键修复，再打开发现没有报错了，且内部逻辑已经恢复。

其实到这一步我不知道算不算脱壳成功了，所以就往后在尝试一下重新构建后的app能不能直接运行

三.脱壳后重建

1.静态分析

分析代码的过程由dsh完成

分析classes07.dex，查看 MainActivity：

  • 110 个方法中，109 个有完整 Java 实现。
  • 被抽空的是 onCreate和n方法，声明为 protected native void onCreate(Bundle)，code_off=0，没有任何字节码。
  • static {} 里只有一行：StubApp.interface11(5901)，其中 5901 = class_def 索引 5900 + 1，是 360 加固的类注册回调。

继续分析发现：

p() 是真正的 initView：

  • 16 次 findViewById（shelf_rl、bookstore_rl、forum_rl、shelf_tv 等）
  • 8 次 setOnClickListener
  • 创建广播接收者 MainActivity$22
  • 调用 a()

全 DEX 交叉引用扫描确认：p() 没有任何 Java 调用者，只能由 native onCreate 通过 JNI 回调。

2.动态分析onCreate函数

用Frida 在 android.app.Activity.setContentView(int) 上做了全局 hook，并在 p()/q()/j()/f()/k()/l()/h()/a() 等方法的实现里打印调用栈，从栈帧中的 MainActivity.onCreate(Native Method) 反推 native 侧的回调顺序。 注意全局 hook 会命中所有 Activity，必须按调用栈区分归属：本次捕获到的 2130903152 是 0x7f030070＝layout/activity_guesslike（属于 GuessLike_Act），不是MainActivity 的布局；MainActivity 的是 0x7f030077＝layout/activity_main。

onResume 里调 n()；onClick 里调 a(1)/a(2) 切换 Tab 后调 n()。脚本如下：

console.log("[*] Script loaded, starting anti-debug hooks...");

// ---------- 1. 绕过 ptrace 反调试 ----------
try {
    var ptrace = Module.findExportByName(null, "ptrace");
    if (ptrace) {
        Interceptor.replace(ptrace, new NativeCallback(function (request, pid, addr, data) {
            console.log("[*] ptrace(" + request + ") intercepted, returning 0");
            return 0;
        }, 'int', ['int', 'int', 'pointer', 'int']));
        console.log("[+] ptrace hooked");
    }
} catch (e) {
    console.log("[-] ptrace hook failed: " + e);
}

// ---------- 2. 绕过 exit 主动退出 ----------
try {
    var exit = Module.findExportByName(null, "exit");
    if (exit) {
        Interceptor.replace(exit, new NativeCallback(function (status) {
            console.log("[*] exit(" + status + ") intercepted, blocked");
        }, 'void', ['int']));
        console.log("[+] exit hooked");
    }
} catch (e) {
    console.log("[-] exit hook failed: " + e);
}

// ---------- 3. 绕过 Java 层调试检测 ----------
Java.perform(function () {
    try {
        var Debug = Java.use('android.os.Debug');
        Debug.isDebuggerConnected.implementation = function () {
            console.log("[*] isDebuggerConnected() called, returning false");
            return false;
        };
        console.log("[+] Debug.isDebuggerConnected hooked");
    } catch (e) {
        console.log("[-] Debug hook failed: " + e);
    }
});

// ---------- 4. 延迟观测 MainActivity ----------
// 360 壳会在启动后一段时间才把业务 DEX 加载进来
// 延迟 10 秒，避开启动初期的反调试高峰，等类加载完成

var DELAY_MS = 10000;

setTimeout(function () {
    console.log("[*] Delay finished, trying to hook MainActivity...");

    Java.perform(function () {
        var MainActivity;
        try {
            MainActivity = Java.use('com.example.jinjiangshucheng.ui.MainActivity');
            console.log("[+] MainActivity found!");
        } catch (e) {
            console.log("[-] MainActivity not found: " + e);
            return;
        }

        // 要观测的方法列表（根据你的分析报告）
        var methods = ['p', 'f', 'q', 'g', 'h', 'j', 'k', 'l', 'm', 'a', 'onClick', 'n'];

        methods.forEach(function (methodName) {
            try {
                var overloads = MainActivity[methodName].overloads;
                overloads.forEach(function (overload) {
                    overload.implementation = function () {
                        var argsStr = "";
                        try {
                            argsStr = JSON.stringify(Array.prototype.slice.call(arguments));
                        } catch (e) {
                            argsStr = "[unserializable]";
                        }

                        console.log("\n[CALL] MainActivity." + methodName + "(" + argsStr + ")");

                        // 打印调用栈，定位 native onCreate 的回调时机
                        try {
                            var stack = Java.use('android.util.Log').getStackTraceString(
                                Java.use('java.lang.Exception').$new()
                            );
                            console.log("[STACK] " + stack);
                        } catch (e) {
                            console.log("[STACK] failed: " + e);
                        }

                        return overload.apply(this, arguments);
                    };
                });
                console.log("[+] Hooked: " + methodName);
            } catch (e) {
                console.log("[-] Failed to hook " + methodName + ": " + e);
            }
        });

        console.log("[*] All hooks installed, waiting for calls...");
    });
}, DELAY_MS);

Java.perform(function () {
    var Activity = Java.use('android.app.Activity');
    Activity.setContentView.overload('int').implementation = function (id) {
        console.log('[*] setContentView id=' + id);
        return this.setContentView(id);
    };
});

3.修改smali代码并重建

使用backsmali.jar反编译dex文件，把

.method protected native onCreate(Landroid/os/Bundle;)V
.end method

替换为：

.method protected onCreate(Landroid/os/Bundle;)V
    .registers 3

    invoke-super {p0, p1}, Landroid/support/v4/app/FragmentActivity;->onCreate(Landroid/os/Bundle;)V

    const v0, 0x7f030077                 # layout/activity_main
    invoke-virtual {p0, v0}, Landroid/support/v4/app/FragmentActivity;->setContentView(I)V

    # 原本在 native onCreate 里赋值；a(I) 每次切 Tab 都直接用它做 beginTransaction()
    invoke-virtual {p0}, Landroid/support/v4/app/FragmentActivity;->getSupportFragmentManager()Landroid/support/v4/app/FragmentManager;
    move-result-object v0
    iput-object v0, p0, Lcom/example/jinjiangshucheng/ui/MainActivity;->fragmentManager:Landroid/support/v4/app/FragmentManager;

    invoke-direct {p0}, Lcom/example/jinjiangshucheng/ui/MainActivity;->p()V

    const/4 v0, 0x0
    invoke-direct {p0, v0}, Lcom/example/jinjiangshucheng/ui/MainActivity;->a(I)V

    return-void
.end method

并清理所有StubApp引用，最后重新打包，出现了闪退

4.后续

然后就一直让dsh解决闪退的问题，最后也有点疲惫了，就没有再去补了，补到最后的效果就是：进主页、切三个 tab、进个人中心、书架有真实书目、书城子 tab，但是点击搜索书名会闪退。
